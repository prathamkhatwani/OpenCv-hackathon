# Deployment and competition handoff

## AWS target

Run the meaningful OpenCV workload on an **EC2 Linux x86-64 instance**, rather than only hosting static HTML on AWS. Start with 2 vCPU/4 GB RAM for a bounded team demo and measure actual memory/latency before opening access. This is a planning estimate, not a performance result. Keep a persistent EBS volume and backups. The ZIP has not been deployed to an AWS account.

1. Provision an instance, restrict SSH to your IP, allow public HTTPS/HTTP for certificate issuance, and keep port 8000 private. Install Docker Engine/Compose v2 and an HTTPS reverse proxy such as Caddy.
2. Copy/extract the project; copy `.env.example` to `.env`. Replace both placeholders with independent random secrets (for example generated by Python `secrets.token_hex(32)`). Set your real HTTPS origin. Do not commit `.env`.
3. Run `bash roadreport/infra/setup.sh` from the extracted project. It builds and starts one app container. The UI is served on the API's origin; the container binds only host loopback port 8000. Docker/EC2 deployment remains an unexecuted recipe in this delivery.
4. Adapt `roadreport/infra/Caddyfile` to your DNS name; point DNS at the instance; run Caddy on the host. Its HTTPS endpoint proxies localhost:8000. Verify certificates before using phone Capture.
5. Put the team API key into the dashboard. This is shared-team access, not a multi-user permission system. Health is public; API data is keyed; local evidence uses short-lived signed bearer URLs. Anyone holding an evidence URL can read it until expiry; don't publish those links.
6. Verify `/api/health` reports OpenCV **5**, upload a team-owned video, inspect actual traces, persist a review, export PDF, restart and check history. Capture EC2 runtime/region, logs, instance type, architecture and measured processing time for submission.

For private S3, attach an EC2 instance role scoped to your bucket prefix with GetObject/PutObject permissions and relevant KMS permissions if needed. Set `USE_LOCAL_STORAGE=false`, `S3_BUCKET`, `AWS_REGION`. Keep Block Public Access enabled. Do not put AWS keys in the frontend. This code's S3 integration uses boto3 and signed GETs; actual S3 permissions/network behavior must be verified in your account. SQLite still needs the persistent `/data` volume.

The in-process queue handles one running and one waiting analysis. Do not scale replicas/workers against the same SQLite database. Restart interrupts queued/running jobs, marks them failed on startup, and requires reupload. Phone camera, TLS, Docker image build, AWS/S3 and ARM behavior are not certified by local software tests.

## Submission focus

Use the current official competition pages to reconfirm rules and deadlines: https://opencv26.devpost.com/ and https://opencv26.devpost.com/rules . The original audit in this ZIP records the rule conflicts encountered at review time. Resolve eligibility/team-size/deadline discrepancies with the organizers; don't assume code changes resolve registration requirements.

Prepare:

- Substantive OpenCV 5 demonstration and verifiable AWS execution.
- Working endpoint or agreed demonstration access; source repository with this lockfile and setup instructions.
- Architecture, dataset/media/model provenance, actual held-out evaluation and failure analysis.
- A concise video within the competition's stated limit, plus the requested written report. Recheck official submission limits before uploading.
- Agentic Vision evidence: show an uncertain case causing native-frame reinspection, its recorded score change, and a human-review escalation. This bounded policy is genuinely action-selecting but is not an LLM.
- COOL is an optional separate path: only claim it after running the substantive workload on the required ARM/Graviton environment and recording a reproducible comparison. This package does not establish COOL eligibility.

## Suggested demo sequence

1. Open a real pothole observation whose wheels miss it: explain the preserved visual finding and no-contact geometry.
2. Show a separate case with expected contact and a correctly aligned impact; distinguish correlation from validated contact.
3. Show a speed bump/shadow/unrelated shake that does not become a pothole just because the camera moved.
4. Show reinspection, uncertainty, saved human review and the resulting report.
5. Show the real AWS/OpenCV runtime and honest held-out metrics, including failures.

This is a coherent evidence story, not a guarantee of an award. Training, real footage collection, calibration, cloud execution and final submission remain team tasks.
